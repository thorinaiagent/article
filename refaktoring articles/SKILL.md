# Редактура статьи red_mad_robot

Последовательность действий при задаче «отредактируй статью».

## Шаг 0. Загрузить правила

Прочитать оба файла с правилами — это источник истины для правки:

- `правила-редактуры.md` — правила редактуры, выведенные из редполитики и разбора статей блога (структура, голос, технический контент, кейсы, заголовки, чек-лист вычистки).
- `правила/redpolitika.md` — официальная редполитика компании (грамотность, ToV, канцелярит и клише, оформление, сложные случаи написания).

При конфликте приоритет — у более конкретного правила; общий тон и терминология всегда по редполитике.

## Шаг 1. Прочитать входящую статью

Открыть файл со статьёй, который дал автор (Markdown, txt или вставленный текст). Полностью прочитать, понять тему, аудиторию и площадку (Хабр / vc.ru / соцсети — от этого зависит режим ToV).

## Шаг 2. Сверить текст и структуру с правилами

Пройтись по статье и сопоставить с правилами:

- **Структура** (раздел 1 правил): есть ли заход через проблему, представление автора одним предложением, анонс содержания, разбивка на подзаголовки-тезисы, вывод/ограничения в конце. Если чего-то нет — пометить.
- **Голос и лексика** (раздел 2 + редполитика 1.3–2): канцелярит, клише, декоративные метафоры, лишний юмор, корпоративные штампы.
- **Технический контент** (раздел 3): поясняются ли термины, есть ли цифры с источником, проговорены ли ограничения метода, не оборваны ли причинно-следственные связи.
- **Заголовок** (раздел 5): по схеме «[технология]: [конкретная польза]».
- **Чек-лист вычистки** (раздел 6): написание `red_mad_robot`, «этот» вместо «данный», «frontend-разработчик», «офлайн» и прочие случаи из таблицы.

Сформулировать список конкретных правок, а не общее впечатление.

## Шаг 3. Отредактировать статью

Внести правки **с сохранением авторского голоса и фактов**:

- не переписывать текст целиком — трогать только те места, которые реально нарушают правила или делают текст хуже;
- сохранять формулировки и ритм автора там, где они не нарушают правила;
- если фрагмент требует фактуры, которой нет (цифра без источника, оборванная логика) — не выдумывать, а пометить комментарием для автора;
- если правка спорная (например, вопрос стиля, а не ошибки) — предложить вариант и объяснить, а не молча менять.

Сохранить отредактированную версию в Markdown-файл (например, рядом с исходником, с суффиксом `-edited.md`).

## Шаг 4. Собрать DOCX

Запустить скрипт из папки скилла:

```
python3 "make_docx.py" <путь_к_отредактированному.md> "Название статьи"
```

Скрипт конвертирует Markdown в DOCX и сохраняет его в папку **`~/Desktop/Отредактированные статьи/`** (создаётся автоматически). В имя файла добавляются дата и время, чтобы версии не перетирали друг друга.

Если скрипт сообщит, что не установлена библиотека, выполнить один раз:

```
pip3 install python-docx
```

## Шаг 5. Сообщить автору

Вывести:

- полный путь к готовому DOCX (его печатает скрипт последней строкой);
- краткое резюме внесённых правок (что и почему поменяли);
- список мест, помеченных для автора (недостающие цифры, источники, спорные формулировки).

Хвалить текст без повода не нужно. Если всё хорошо — сказать коротко. Если есть проблемы — назвать их прямо.
